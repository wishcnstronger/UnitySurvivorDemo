# 提交当前改动

用户输入 `/commit` 时，按以下步骤执行：

1. 运行 `git status`，了解本次改动了哪些文件。
   - 如果工作区是干净的（没有待提交内容），直接告诉用户"没有需要提交的改动"，然后停止。
2. 运行 `git diff --stat` 了解改动规模，必要时用 `git diff` 读取具体改动内容，以便生成准确的提交信息。
3. 确定提交信息：
   - 如果用户在 `/commit` 后面附带了文字（例如 `/commit 完成玩家武器`），直接用它作为提交信息。
   - 否则，先运行 `git log --oneline -10` 查看最近提交风格，再根据本次改动内容生成一条中文提交信息。
4. 提交信息格式参考项目历史：
   - 功能改动用 `phaseX 中文描述`（例如 `phase2 怪物系统`）。
   - 杂务改动（换行符、gitignore 等）用 `chore: 中文描述`。
   - 尽量一句话概括本次改动的核心内容。
5. 运行 `git add -A` 暂存全部改动。
6. 运行 `git commit -m "<提交信息>"` 提交。
7. 运行 `git log --oneline -1` 确认提交成功。
8. 简要汇报给用户：本次提交信息、提交了哪些文件。不要自动 push，除非用户明确要求。

## 注意事项

- 不要拆分多次提交，一次 `/commit` 只做一次提交。
- 如果用户说"先别提交"或要求先做其他事，不要提交。
- 保持提交信息简洁、符合项目风格，不要生成长篇描述。
